# 核对结果

AI 说「我测过了」不算数，所以每一版我们都自己核了一遍。这里写清楚：怎么核的、核出来什么、哪些地方没核到。

**先说最要紧的一句：** 这里所有「全对」说的都是那 85 个样例。样例是我们自己造的，版式也是我们自己排的，它认发票的规则又是照着这批样例写出来的，所以在样例上全对并不稀奇，**说明不了它读真发票的本事**。真发票我们一张都没试过。

## 怎么核的

造样例的时候，脚本同时写下了一份 `样例发票/标准答案.json`：每个文件是什么（发票、重复的、纯图片、不是发票）、号码、日期、销售方、购买方、价税合计、税额、项目。录制时这份答案和造样例的脚本都没有放进 AI 能看到的文件夹，它只能照发票上的字去读。

核对用了三种办法：

1. **真跑一遍，拿产物逐格比**（`check_run.py`）。先看原来的发票有没有被动过（逐个比文件指纹），再把输出文件夹里每个文件按内容对回原件，看它被放进了哪个文件夹、改成了什么名字，最后打开汇总表一格一格和标准答案比。
2. **放进浏览器内核里自动跑**（`regress.mjs`、`dup_test.mjs`、`phone_test.mjs`、`browser_run.mjs`、`phone_shot.mjs`）。把 85 个样例喂给页面，读出它认出的每一格和标准答案比；同时掐断网络，记下它有没有往外发请求。
3. **把认发票的那段逻辑单独拿出来**，喂几种样例里没有的写法，看它怎么判（`edge_cases.mjs`）。这些发票文字是我们照常见写法自己拟的，也不是真发票。

## 每一版的结果

| 版本 | 他说的那句话 | 核对结果 |
|---|---|---|
| v1 第一版（41 KB，要联网取组件） | 做一个软件，批量改名、自动分类、导出表格、标记重复 | 他本人在自己的浏览器里真跑了一次，产物逐格比：85 个原件一个没动；80 张发票的日期、销售方、购买方、号码、价税合计、税额、项目全部对；合计 29914.93 元对；3 张重复、1 张纯图片（没被瞎填）、1 份行程单都放对了地方；汇总表的合计行和分类汇总对。**问题：没有。** 85 个文件读完约 1 秒。连不上放组件的网站时，给的是看得懂的提示。 |
| v2 断网也能用（1.8 MB） | 可以，下载吧……最好还是只发一个文件就行 | 掐断网络跑：85 个全对，没有一次往外联网。 |
| v3 界面改版 | 网页布局设计有点混乱……需要进行UI排版的美化 | 85 个全对，断网可用，页面没有报错。 |
| v4 重复发票对比 | 重复发票里……对比两张……保存哪一张，重复的另一张如何处理 | 85 个全对，断网可用。它给的办法是三选一：另一张单独放进「重复发票」（默认）、不放进整理结果、「它们不是重复，都保留」。三组重复各用一种办法跑了一遍：输出的文件、完成窗口里的数、汇总表的备注和合计都对（选「都保留」之后正常发票 81 张、合计 30059.38 元），原件 85 个没动。它没有做「删除原文件」，并说明了为什么。 |
| v5 手机适配（最终版） | 我把这个文件传到了手机，发现排版全乱了。 | 电脑上选文件夹那条路：85 个全对、断网可用。模拟的手机屏（412 宽，拿掉了选文件夹的功能）：页面不再比屏幕宽；主按钮自动变成「选择发票文件」；选 85 个文件读出来逐格全对；看原件是它自己画出来的（一块画布）；「整理并打包下载」得到的压缩包解开后是 85 个文件加汇总表，拿标准答案核全对，中文文件名正常。 |

另外查过的两件事：

- 五个版本里它自己写的那部分代码，没有任何删除或移动文件的调用。它只往你选的文件夹里**新建**一个「整理好的发票_日期_时间」，把发票**复制**进去。
- 改版之前的 v4 放进模拟的手机屏，读完 85 张以后页面宽 725，屏幕宽 412，表格被切掉一大截。这就是他那句「排版全乱了」。（真手机上当时的样子没有留图，这个数是模拟出来的。）

把这些东西整理进仓库的时候（2026-10-11），我们用这个文件夹里改过路径的脚本又全部重跑了一遍，结果和上面一致。

## 样例之外的情况

用 `edge_cases.mjs` 试的，文字是我们自己拟的。

**对的：** 多行项目加合计行、金额带逗号（`¥14,000.00`）、红字发票（负数）、老式的「发票代码 12 位 + 号码 8 位」、同一天同一家同样金额的几张发票（文件名自动加 `(2)` `(3)`，不会互相覆盖）。

**不对的（最终版里仍然如此）：**

| 情况 | 它怎么判的 |
|---|---|
| 销售方名字里有空格，比如 `ABC Trading (Shanghai) Co., Ltd.` | 只取到第一个空格前面：`ABC`。状态仍是「正常」，不会提醒。 |
| 销售方名字太长，在发票上折成了两行 | 只取到第一行。状态仍是「正常」，不会提醒。 |
| 没有销售方的票（火车票那一类） | 进「需要人工检查」。 |
| OFD 格式的发票、拍的照片 | 都进「需要人工检查」。照片这么说没错；OFD 的备注写的也是「图片或扫描件，读不出文字」，这句不准确，它其实是不支持 OFD。 |
| 免税的发票（税额栏是 `***`） | 价税合计能读到，「金额(不含税)」和「税额」两格留空。 |

还有一处小的：在 v4 以后选了「它们不是重复，都保留」的那两张，汇总表里没有注明它们号码相同、是你手动保留的。

这些我们故意没让它改，留在 README 的「已知的毛病」里给你练手。

## 没核对到的地方

- **真发票**：一张都没试过。
- **真手机**：他在自己的手机上看过最终版，排版没问题。选文件、打包下载这条路在真手机上没有逐项核；**微信里打开、苹果手机**都没试。上面手机那一行是在电脑上模拟的手机屏。
- **Excel 和 WPS**：汇总表没有专门在这两个软件里核过。录制的那台电脑上没装它们；AI 是在 LibreOffice 里打开看的，我们是用程序读的表。
- **电脑上右边的「查看原件」**：用的是浏览器自带的 PDF 阅读器，自动测试的浏览器内核显示不了，这一块没能自动核。

## 想自己重跑一遍

要先装 Node.js（18 或更新）。`edge_cases.mjs` 只要 Node.js；其余几个 `.mjs` 还要装 playwright（装法写在 `_common.mjs` 开头）；`check_run.py` 要 Python 和 openpyxl。都在「核对」这个文件夹里运行：

```
node edge_cases.mjs ../发票整理助手.html
node regress.mjs ../版本/v1-第一版.html
node regress.mjs ../版本/v2-断网也能用.html --offline
node regress.mjs ../发票整理助手.html --offline
node dup_test.mjs ../发票整理助手.html
node phone_test.mjs ../发票整理助手.html
node phone_shot.mjs ../版本/v4-重复发票对比.html v4
node browser_run.mjs ../版本/v1-第一版.html
python check_run.py ../样例发票 "../样例发票/整理好的发票_（你自己跑出来的那个文件夹）"
```

`regress.mjs` 不加 `--offline` 测 v1 时，页面会像平时一样去 cdnjs.cloudflare.com 取 pdf.js。脚本产生的截图、表格、压缩包都放在 `核对/输出/` 里，不会碰别的地方。
