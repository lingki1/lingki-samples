# 项目说明（每次新对话先读这份）

## 这是什么

一个 Python 小软件：把「学生作业」文件夹里的 Word 作业批量改成《格式要求.docx》规定的格式，结果写进「排版结果」，并生成一张 Excel 处理报告。

完整的方案在 `文档/` 里，已经过老师确认，是做事的依据：

- `文档/1-技术栈.md`　用哪些工具、为什么
- `文档/2-设计方案.md`　现状、规则表、三条底线、流水线、已拍板的决定
- `文档/3-开发步骤.md`　七个步骤，每步的完成标准
- `文档/4-代码审查.md`　交付前的代码审查：29 组发现，哪些修了、哪些不修、为什么

## 和谁一起做

用户是一位高中老师，**不会编程**，用中文交流。

- 用大白话讲。用到术语就顺手解释，不要甩代码和报错原文给老师看。
- 汇报时说三件事：做了什么、检查结果如何、有没有意外。检查没通过就照实说。
- 老师不看代码，看的是「排版结果」里的文件和「处理报告.xlsx」。

## 做事的规矩

1. **按步骤来，到检查点就停。** 步骤见 `文档/3-开发步骤.md`。第 1、3、6 步做完必须停下来请老师看，老师点头再继续。其余步骤可以连着做。
2. **原件绝不动。** 「学生作业」「格式要求.docx」「名单.xlsx」只读（「老师的决定.xlsx」只在老师有新决定时才改）。程序和开发过程中的任何试验都不许往「学生作业」里写东西；需要转换或试验时先复制到临时文件夹。
3. **一个字都不能少。** 排版前后的文字要逐字比对，图片、表格数量要一致。按规定会变的只有姓名行和小标题的编号，这两处单独核对。
4. **认不准就不猜。** 缺姓名、缺学号、缺题目、重复提交、认不出的文件，放进「需人工确认」并写明原因，不替老师和学生做决定。
5. **先写检查，再写功能。** 每个功能都要有对应的自动测试；改完代码跑全部测试，全部通过才算完成。
6. **每完成一步用 git 存档一次**，说明写清这一步做了什么。只在本机存档，不推送到任何地方。
7. **不联网、不上传。** 学生作业和名单是个人信息，不进 git（见 `.gitignore`），不发给任何外部服务。
   - 这条管的是**程序和存档**。要清楚两件事并如实告诉老师：① Claude 读文件，内容就会随对话发到 Anthropic 的服务器，所以读新一批作业、名单之前先跟老师说一声；② `pip install` 会联网下载库，做之前先说。（2026-10-11 这两件事都是事后才向老师说明的，不要再犯。）
   - 跑测试会在系统临时文件夹 `pytest-of-（用户名）` 里留下排好版的作业副本（保留最近 3 次），交付前要清理或告知。
8. **只做范围内的事。** 不改学生写的内容，不转换 PDF，不做图形界面，不打包 exe，不评分。老师提了新需求再加。
9. **方案有变动先改文档。** 规则或设计要调整时，先和老师说清楚，同步更新 `文档/`，再改代码。

## 老师已经拍板的决定（2026-10-11）

1. 用「名单.xlsx」（两列：学号、姓名）补全缺的学号，并列出谁没交。
2. 正文里学生自己加的加粗、黄色高亮**都去掉**，报告里注明。
3. 「参考资料」四个字按小标题排，下面的条目按正文排（首行缩进两字）。
4. 写在页眉里的姓名学号挪到题目下面，页眉清空。
5. 拿不准的文件一律不猜，放进「需人工确认」。

后来追加的决定：

6. 个别文件的处理记在「老师的决定.xlsx」里，程序照办（说明见 `文档/2-设计方案.md` 第 8 节）。老师再有类似决定时，替老师在表里加一行，不要改原件。目前两条：匿名的那份是童年（20240321）的；梁思齐以文件名带 (1) 的那份为准，另一份不要。

7. **需求变更（2026-10-11）：小标题的编号统一成「一、」「二、」「三、」。** 按出现顺序重新编号；「参考资料」等不编号；混用两种编号、部分编号、「第一部分」写法、Word 自动编号这几种拿不准的情况不改，放进「需人工确认」。细节见 `文档/2-设计方案.md` 第 9 节，其中三条是替老师定的，验收时要请老师过目。
8. 参考资料的条目按正文缩进、表格里的字居中：老师看过效果后确认（2026-10-11）。

学校没写、已经替老师定下的细节（老师已同意）见 `文档/2-设计方案.md` 第 2 节末尾。

## 技术栈

| 用途 | 工具 |
|---|---|
| 语言 | Python 3.10（独立环境在 `.venv/`） |
| 读写 .docx | python-docx 1.2；够不着的细节用 lxml 直接改 |
| 旧版 .doc 转 .docx | 后台调用 LibreOffice（`C:\Program Files\LibreOffice\program\soffice.exe`） |
| 处理报告 | openpyxl（Excel） |
| 规则表 | `规则.toml`，用 tomli 读（中文名字必须带英文引号，否则读不了） |
| 测试 | pytest |
| 肉眼核对（仅开发时） | LibreOffice 转 PDF，再用 PyMuPDF 转成图片来看 |
| 版本管理 | git，只在本机 |

版本固定在 `requirements.txt` 和 `requirements-dev.txt`。

**这台电脑的情况：** Windows 11，**没有装微软 Word**，只有 LibreOffice 26.2。所以排版效果只能用 LibreOffice 验证，最终要请老师在学校的 Word 或 WPS 里抽看。黑体、楷体、宋体、Times New Roman 系统里都有。

## 常用命令

在项目文件夹里运行（Git Bash 写法）：

```bash
.venv/Scripts/python -m pytest                              # 跑全部测试
PYTHONPATH=src .venv/Scripts/python -m homework_formatter    # 运行程序，结果在「排版结果/日期_时间/」
.venv/Scripts/python -m pip install -r requirements-dev.txt  # 重建环境时用
```

换了电脑要重建运行环境：先确认装了 Python 3.10+ 和 LibreOffice，然后在项目文件夹里
`python -m venv .venv`，再运行上面最后一条命令（这一步要联网下载库，只下载公开的库，不上传任何东西）。
建完跑一遍全部测试。

老师平时用的是 `开始排版.bat`（双击）。这个文件必须是 UTF-8 编码、Windows 换行（CRLF），里面的 echo 不要用英文括号；要改它请改完后实际双击或用 `cmd /c "完整路径"` 跑一次。

代码没有安装成包，靠 `PYTHONPATH=src` 找到（pytest 已在 `pyproject.toml` 里配好）。原因：项目路径里有中文和空格，这样最省事。

## 文件夹结构

```
格式要求.docx      学校原文（只读）
学生作业/          原件（只读，不进 git）
名单.xlsx          班级名单（只读，不进 git）
老师的决定.xlsx    老师对个别文件的决定（不进 git）
排版结果/          程序生成，每次运行新建一个带时间的子文件夹（不进 git）
文档/              方案文档
开始排版.bat       老师双击运行的入口
使用说明.md        写给老师的使用说明
规则.toml          格式规则表
src/homework_formatter/   程序代码
tests/             自动测试
```

用真实作业做的测试在「学生作业」不存在时会自动跳过。

`src/homework_formatter/` 里已有的模块：

| 文件 | 管什么 |
|---|---|
| `scanner.py` | 列出文件、按内容分清类型、算指纹 |
| `roster.py` | 读名单 |
| `identity.py` | 从正文、页眉、文件名、名单里找姓名和学号 |
| `decisions.py` | 读「老师的决定.xlsx」 |
| `structure.py` | 认结构：每一段是题目、姓名行、小标题还是正文 |
| `reader.py` | 读出 .docx 的段落、页眉、表格和图片数量 |
| `converter.py` | 调 LibreOffice 把 .doc 转成 .docx（在临时文件夹里） |
| `inventory.py` | 点名：每个文件的去向和原因，重复提交的比对 |
| `rules.py` | 读「规则.toml」 |
| `numbering.py` | 小标题编号：认出学生的写法，统一成「一、二、三」，拿不准就不给方案 |
| `formatter.py` | 排版：先清掉旧格式，再按规则表明确写上新格式；认出没见过的结构并提醒 |
| `integrity.py` | 底线检查：排版前后逐行比对文字，图片、表格、公式等数量不变。**故意不用 structure.classify**（否则认错时和排版一起错） |
| `checker.py` | 质检：重新打开排好的文件，逐条核对规则；不调用 formatter。格式检查是**白名单**式的：只允许列出的那几样设置 |
| `pipeline.py` | 流水线：点名 → 排版 → 比对 → 写文件 → 出报告，负责运行前后的原件核对 |
| `report.py` | 写处理报告.xlsx |
| `__main__.py` | 命令行入口：读名单、决定表、规则表，打印结果 |

`tests/test_real_samples.py` 里有人工核对过的 38 个文件的正确答案；`tests/test_real_formatting.py` 把真实作业完整排一遍，逐份逐段对照 8 条要求。

`tests/test_cr_findings.py` 是代码审查发现的问题的复现检查，编号（CR-01…CR-29）对应 `文档/4-代码审查.md`。

**换一批作业（换班、下一次作业）时**：`test_real_samples.py`、`test_real_formatting.py` 和 `test_converter.py` 里写死了这一批的正确答案（38 个文件、33 份完成、具体人名），会不通过。那不是程序坏了。要么按新一批重新人工核对后更新答案，要么把「学生作业」换回这一批再跑。pytest 已设置 `-rs`：有检查被跳过时会列出原因。

`tools/make_comparison.py` 把排版前后的作业并排画成图片（给老师看效果用，也是自己肉眼核对的办法）：

```bash
.venv/Scripts/python tools/make_comparison.py 排版结果/某次运行 原文件名1 原文件名2
```

写脚本时注意：这里的 Bash 工具会把 heredoc 里的反斜杠转义吃掉，带 `\n` 之类的内容要用 Write/Edit 工具写文件，不要用 heredoc。
