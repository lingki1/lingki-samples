# 技术栈（要用到哪些工具，为什么）

> 项目：研究性学习小报告 · 批量排版小软件
> 日期：2026-10-11　状态：**老师已于 2026-10-11 确认**

## 一句话

用 Python 写一个双击就能运行的小程序。它读「学生作业」里的文件，在一个新文件夹里生成排好版的副本，并附一张处理报告。原件只读不写。

## 选用的工具

| 用途 | 工具 | 为什么选它 | 这台电脑上 |
|---|---|---|---|
| 编程语言 | Python 3.10 | 您指定用 Python；3.10 足够，不需要升级 | 已装 3.10.6 |
| 读写 Word（.docx） | python-docx 1.2 | 最常用、最稳定的 Word 处理库；能改字体、字号、段落、页面 | 已装 |
| 处理库够不着的细节 | lxml | 页码、"首行缩进 2 字符"、中文字体这几项，python-docx 没有现成按钮，需要直接改 Word 文件内部的标记 | 已装 |
| 旧版 .doc 转 .docx | LibreOffice（后台调用） | python-docx 读不了旧版 .doc。这台电脑**没有装微软 Word**，但装了 LibreOffice，我已用它试转两份 .doc，内容完整 | 已装 26.2 |
| 处理报告（Excel 表） | openpyxl | 报告做成 Excel，您可以筛选、排序、打勾 | 已装 |
| 读取规则表 | tomli | 格式规则单独放在一个文本文件里，不和程序混在一起 | 已装 |
| 自动化测试 | pytest | 每写一块功能就配一组自动检查，以后改动不怕改坏 | 已装 |
| 肉眼核对（仅开发时用） | LibreOffice + PyMuPDF | 把排好的文件转成图片，我逐页看效果，不靠猜 | 已装 |
| 版本管理 | git（只在本机） | 每完成一步存一个"存档点"，改坏了可以退回 | 已装 2.48 |
| 运行环境隔离 | venv（Python 自带） | 给这个项目单独一套库，不受电脑上其他 Python 程序影响 | 自带 |

**不需要另外下载安装任何东西。**

> **更正（2026-10-11）：** 上面这句话不准确。这些工具电脑上确实都已经有了，但开发时我给项目单独建了一套运行环境（项目里的 `.venv` 文件夹，约 99 MB），并从 Python 官方软件库（pypi.org）重新下载了一份这些库，约 26 MB。当时没有先告诉您。没有安装任何系统级的软件，电脑上原有的 Python 没有被改动。

## 几个刻意的"不用"

- **不做图形界面。** 双击一个 `开始排版.bat` 就运行，结果放进文件夹。界面要多写不少代码，而您要的只是"一次全部改好"。以后想要可以再加。
- **不打包成 exe。** 在您自己的电脑上用，双击 bat 就够了。如果以后要发给同事，再打包。
- **不让程序自己"读懂"《格式要求.docx》。** 那是写给人看的话，程序理解不可靠。做法是：我把 8 条要求逐条翻译成一张规则表（见《2-设计方案》第 2 节），您核对这张表就行。学校以后改要求，改这张表。
- **不转换 PDF。** PDF 转 Word 会丢格式、乱顺序（我试读了齐悦的 PDF，文字顺序是乱的）。这类文件列进报告，请学生重交 Word 版。
- **不联网、不上传。** 学生作业是个人信息，全程只在本机处理；git 存档也只在本机，而且不把学生作业放进存档。

  > **更正（2026-10-11）：** 这句话只对**软件本身**成立：它运行时不联网、不上传。但**开发过程**不是这样：Claude 是在线服务，我（以及代码审查时的三位审查员）读过的作业内容、姓名、学号和名单，都作为对话的一部分发送到了 Anthropic 的服务器。"全程只在本机处理"的说法对开发过程不成立，当初应该在读文件之前就向您说明。

## 一个需要您知道的限制

这台电脑没有微软 Word，所以我只能用 LibreOffice 检查排版效果。两者对同一份文件的显示绝大多数情况一致，但不是百分之百。交付前请您在学校的 Word 或 WPS 里抽看两三份，这一步我替不了。
