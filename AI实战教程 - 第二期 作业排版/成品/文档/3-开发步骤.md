# 开发步骤

> 项目：研究性学习小报告 · 批量排版小软件
> 日期：2026-10-11　状态：**老师已于 2026-10-11 确认**

## 正规流程是什么样的

```
需求 ──→ 设计 ──→ 分步开发（每步：先写检查，再写功能） ──→ 验收 ──→ 交付
 ✔        ✔        ← 现在在这里
```

- **需求**：您提的要求 + 学校的《格式要求.docx》。已明确。
- **设计**：《1-技术栈》《2-设计方案》。等您确认。
- **分步开发**：分成下面 7 步。每一步都小到能说清"做完是什么样"，做完给您看结果，再做下一步。
- **验收**：您亲自打开结果看，您说行才算行。
- **交付**：双击就能用的程序 + 使用说明。

两条贯穿始终的做法：

- **先写检查，再写功能。** 比如要做"题目改成黑体二号"，先写一段自动检查"题目是不是黑体二号"，它此时必然不通过；再写功能让它通过。这样每个功能都有一把尺子量着，以后改别处时不小心碰坏了，尺子会马上报警。
- **每步存档。** 每完成一步用 git 存一个存档点，写明这一步做了什么。

## 七个步骤

### 第 0 步　搭架子

- 做什么：建好文件夹结构、独立的运行环境、git 存档、一个最简单的"能跑起来"的检查。
- 做完的标准：运行测试命令，显示"1 个通过"。
- 您能看到：文件夹里多出 `src/`、`tests/` 等，「学生作业」原封不动。

### 第 1 步　点名（只读，不排版）

- 做什么：扫描文件夹；分清 .docx / .doc / PDF / 临时文件；从正文、页眉、文件名里找出姓名和学号；有名单就对照名单；给原件算指纹。旧版 .doc 的转换原本排在第 4 步，但点名要读正文，所以提前到这一步做（在临时文件夹里转换副本，原件不动）。
- 做完的标准：程序自己得出的结果，和《2-设计方案》附录那张 38 行的表完全一致。
- 您能看到：第一版 `处理报告.xlsx`（只有点名结果，还没有排版）。**请您核对这张表。**

### 第 2 步　认结构

- 做什么：判断每一段是题目、姓名行、小标题、正文、表格还是图片。
- 做完的标准：36 份 Word 作业的题目和小标题全部认对（我已经人工看过每一份，知道正确答案，会把它们写成检查）。
- 您能看到：报告里多出"认出的题目""认出的小标题"两列。
- 追加（2026-10-11）：这一步顺带做了「老师的决定.xlsx」，用来记录您对个别文件的决定（见《2-设计方案》第 8 节）。

### 第 3 步　排版（核心）

- 做什么：按规则表设置页面、题目、姓名行、小标题、正文、表格、图片、页码；按"学号-姓名.docx"保存。先只做情况规整的 .docx，特殊情况留到第 4 步。
- 做完的标准：8 条要求每条都有自动检查并通过；排版前后文字逐字一致。
- 您能看到：`排版结果/` 里的第一批文件。我会挑 4 份有代表性的（普通的、带图的、带表的、原来最乱的）转成图片，把前后对比给您看。**请您打开几份看看。**

### 需求变更　小标题编号统一（2026-10-11，插在第 3 步和第 4 步之间）

- 做什么：老师看过第 3 步的结果后提出，小标题的编号要统一成「一、」「二、」「三、」。按流程先改《2-设计方案》（第 9 节），再写检查，再改程序。
- 做完的标准：真实作业里四种写法（「一、」「1.」「（一）」、不编号）排完都是「一、二、三」；「参考资料」不编号；拿不准的情况不改并转入需要确认；文字比对照样通过。

### 第 4 步　特殊情况

- 说明（2026-10-11）：下面几项里，"旧版 .doc 的排版""页眉里的姓名学号挪到正文""软回车拆段"已经在第 3 步做完——它们本身就是第三条、第五条格式要求的一部分，拆不开。第 4 步剩下的是：把需要确认的作业（比如缺题目的）也排好版放进「需人工确认」文件夹，以及检测这批作业里没出现过的东西（文本框、批注、修订痕迹、自动编号等）。
- 做什么：旧版 .doc 转换后的排版；页眉里的姓名学号挪到正文；软回车拆段；重复提交、缺题目、匿名、空白、PDF 分别归类。
- 做完的标准：38 个文件每一个都有明确去向——已完成 30，需确认或未处理 7，忽略 1（如果您提供了名单，数字会相应变化）。
- 您能看到：`已完成/` 和 `需人工确认/` 两个文件夹，以及完整的报告。

### 第 5 步　质检

- 做什么：写一个独立的"验收员"程序，重新打开每一份输出，逐条核对 8 条要求、文字完整性、图表数量；核对原件指纹。
- 做完的标准：30 份全自动的作业质检全部通过；我故意做几份"坏文件"（比如把字体改错），质检能把它们抓出来。
- 您能看到：报告"总览"页上的质检结论。

### 第 6 步　一键运行 + 使用说明 + 验收

- 做什么：做 `开始排版.bat`；写《使用说明》（怎么运行、报告怎么看、常见问题、学校改了要求怎么办）；从头到尾完整跑一遍。
- 做完的标准：在一个干净的文件夹副本里，只凭《使用说明》就能跑通。
- 您能看到：双击 → 等几十秒 → 出结果。**请您在学校的 Word 或 WPS 里抽看两三份，这是最后一道验收。**

## 完成情况（2026-10-11）

七个步骤和中途的一次需求变更都已做完，等最终验收。各步的结果记在项目文件夹的 `CLAUDE.md`「进度」一节。

## 不在这次范围内

说清楚不做什么，免得期望落空：

- 不改学生写的内容（错别字、标点、小标题编号的写法）。
- 不转换 PDF。
- 不做图形界面，不打包成 exe。
- 不评分、不查重。

这些以后想加都可以，属于新的需求。
